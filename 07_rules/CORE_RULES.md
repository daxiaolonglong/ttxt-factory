# 完美头条智能工厂 · 核心规则(CORE_RULES)

> 本文件是全项目唯一的核心规则源。所有 Agent、脚本与流程必须遵守。
> 变更本文件需记录原因与日期,并同步更新 `08_wiki/`。

## 一、边界与安全

1. **所有项目文件只允许写入 `D:\ttxt`**。虚拟环境、pip 缓存、浏览器缓存、日志、临时文件、备份全部在项目内;不得写入 D 盘以外(DSH 自身运行目录与用户既有目录除外,且不修改其配置)。
2. **不得擅自修改 Strata 模型、引擎、显存配置、驱动或启动/停止/切换 Strata**。系统只读取模型状态(`/health`、`/v1/models`)并排队调用。
3. **全系统唯一模型执行入口**:任何模型任务必须经过 `model_gate` 统一队列严格串行,任何时候不得并发运行两个模型任务,不得同时启动两个模型。
4. **类目物理隔离**:每个类目独立数据库、RAG 索引、关键词与评审数据,禁止跨类目污染。
5. **不得未经授权发布头条文章**;系统只生成草稿与评审,发布必须人工确认并手动执行。
6. **不得伪造指标**:没有真实来源的阅读/点赞/收藏/评论/曝光数据一律不得写入,数据必须带 `completeness` 与 `credibility`。
7. **不得未经证据授权训练或替换模型**;模型自生成内容不得当作爆款事实回流训练。

## 二、工程纪律

8. 修改老代码前必须先输出**影响面清单**(涉及文件、调用方、数据、回滚方式)。
9. 先梳理架构与完整流程,再改业务代码;不得在未理解现状时动手。
10. 改动前先展示 Diff;每次改动前创建可恢复备份(`11_backups`),并记录回滚位置。
11. 先补测试,再修改,再做回归测试;失败场景必须有测试覆盖。
12. 卡住超过两轮,必须改变技术路线,不得死磕同一方案。
13. 重复踩坑必须写进本规则或对应 Wiki。
14. 需求变化必须同步更新 `08_wiki/`;每阶段结束出具《事实/问题/根因/修改/测试/剩余阻塞/回滚位置》报告。
15. **不得把计划、模拟结果、预测结果冒充实际完成**;验收必须提供真实证据(进程、文件、数据库记录、测试输出、磁盘变化)。
16. 任何失败必须记录根因与恢复方法;不得静默吞掉错误。
17. 临时文件必须设置容量上限与清理周期;清理前必须确认文件不再被使用。

## 三、资源与运维

18. CPU 负责采集、清洗、分析与面板;GPU 只留给 Strata 推理;不得为爬虫占用 GPU。
19. 采集必须遵守 robots.txt、限速与重试退避;不得以绕过登录/访问控制/反爬对抗为目标。
20. 数据库优先 SQLite;不引入 PostgreSQL/Redis/Elasticsearch/向量库等常驻服务,除非有经批准的明确理由。
21. 不创建无实际作用的 Agent、Skill、服务与文档。
22. 删除文件前必须确认目标绝对路径与用途;禁止删除项目外文件。
