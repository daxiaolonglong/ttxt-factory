# 完美头条智能工厂 · 核心规则(CORE_RULES)

> 本文件是全项目唯一的核心规则源。所有 Agent、脚本与流程必须遵守。
> 变更本文件需记录原因与日期,并同步更新 `08_wiki/`。

## 一、边界与安全

1. **所有项目文件只允许写入 `D:\ttxt`**。虚拟环境、pip 缓存、浏览器缓存、日志、临时文件、备份全部在项目内;不得写入 D 盘以外(DSH 自身运行目录与用户既有目录除外,且不修改其配置)。
2. **不得擅自修改 Strata 模型、引擎、显存配置、驱动或启动/停止/切换 Strata**。系统只读取模型状态(`/health`、`/v1/models`)并排队调用。
3. **全系统唯一模型执行入口**:任何模型任务必须经过 `model_gate` 统一队列严格串行,任何时候不得并发运行两个模型任务,不得同时启动两个模型。
4. **类目物理隔离**:每个类目独立数据库、RAG 索引、关键词与评审数据,禁止跨类目污染。
5. **不得未经授权发布头条文章**;系统只生成草稿与评审,发布必须人工确认并手动执行。
6. **不得伪造指标**:没有真实来源的阅读/点赞/收藏/评论/曝光数据一律不得写入,数据必须带 `completeness` 与 `credibility`。
7. **不得未经证据授权训练或替换模型**;模型自生成内容不得当作爆款事实回流训练。

## 二、工程纪律

8. 修改老代码前必须先输出**影响面清单**(涉及文件、调用方、数据、回滚方式)。
9. 先梳理架构与完整流程,再改业务代码;不得在未理解现状时动手。
10. 改动前先展示 Diff;每次改动前创建可恢复备份(`11_backups`),并记录回滚位置。
11. 先补测试,再修改,再做回归测试;失败场景必须有测试覆盖。
12. 卡住超过两轮,必须改变技术路线,不得死磕同一方案。
13. 重复踩坑必须写进本规则或对应 Wiki。
14. 需求变化必须同步更新 `08_wiki/`;每阶段结束出具《事实/问题/根因/修改/测试/剩余阻塞/回滚位置》报告。
15. **不得把计划、模拟结果、预测结果冒充实际完成**;验收必须提供真实证据(进程、文件、数据库记录、测试输出、磁盘变化)。
16. 任何失败必须记录根因与恢复方法;不得静默吞掉错误。
17. 临时文件必须设置容量上限与清理周期;清理前必须确认文件不再被使用。

## 三、资源与运维

18. CPU 负责采集、清洗、分析与面板;GPU 只留给 Strata 推理;不得为爬虫占用 GPU。
19. 采集必须遵守 robots.txt、限速与重试退避;不得以绕过登录/访问控制/反爬对抗为目标。
20. 数据库优先 SQLite;不引入 PostgreSQL/Redis/Elasticsearch/向量库等常驻服务,除非有经批准的明确理由。
21. 不创建无实际作用的 Agent、Skill、服务与文档。
22. 删除文件前必须确认目标绝对路径与用途;禁止删除项目外文件。

## 四、踩坑记录(强制沉淀,不得再犯)

23. **数据身份**:同一类目库内 URL 就是文章身份。`check-then-insert` 必须位于同一个 `BEGIN IMMEDIATE` 写事务内(仅多加一次 SELECT 不算修好并发,因为 Python 默认隐式事务是 DEFERRED,读不加写锁)。来源页/订阅地址不是文章身份:调用 `store.insert_items` 必须传 `page_url`。(2026-11-15,C-2)
24. **验收必须包含"实现前先失败"的测试证据**:新测试在改实现前必须失败并列出失败项;否则无法证明测试有效。测试期望写错时,修测试不改实现语义,并如实记录。(2026-11-15,C-2)
25. **测试隔离**:测试不得连接或写入生产库、生产锁与项目正式文件;pytest 临时目录必须在 `07_tmp/pytest_basetemp` 并按保留份数回收。以 `mode=ro` attach WAL 库会刷新 `-shm` 的 mtime(数据未变),核验要先把库复制到 `07_tmp` 再打开。只读打开 WAL 库会在最后一个连接干净关闭时 checkpoint 空 WAL 并删除 `-wal/-shm` 边车;核验生产库以 `.db` 字节数 + sha 为准,边车存在与否不算改动。(2026-11-14 C-8 / 2026-11-15 C-2 / 2026-11-15 C-3)
26. **类目命名空间所有权**:一篇正式文章只允许属于一个注册类目 —— 别的注册类目已持有(URL 规范化值或 `content_hash`)就不许再往本类目落一行。跨库判定必须是只读存在性查询,且只在写入目标确实位于 `01_categories/<slug>/articles.db` 时执行;未注册命名空间(`demo`)没有拦截权,但注册类目持有的文章能卡住 `demo`。跨库检查与目标库写事务不是同一原子域,兜底是 `doctor` 的 `db.cross_overlap` 对账,不是假装跨文件原子。(2026-11-15,C-3)
27. **conftest 的配置期钩子只在 initial conftest 里被调用**:`pytest`(无参数)或 `pytest .` 时 `10_tests/conftest.py` 要到 collection 阶段才加载,它的 `pytest_configure` 不会被调用,basetemp 退回默认值;本执行环境 `tempfile.gettempdir()` 解析成仓库根,临时库落到 `D:\ttxt\pytest-of-*`,C-8 的临时目录/日志/指纹三重隔离同时失效,表现为一片互不相干的 FAIL。仓库根 `conftest.py` 只前转该配置钩子(夹具仍由原 conftest 注册)。核验必须同时跑 `pytest`、`pytest .`、`pytest 10_tests` 三种调用形式。(2026-11-15,C-3)
28. **派生标签必须如实,且只能有一个口径**:`articles.completeness` 这类"给下游做筛选"的派生字段,取值集合要封闭(三档 `full/short/excerpt`)、判定只在一处定义(`cleaner.completeness_of`,SQL 侧共用 `store.USABLE_LEN_SQL`)、语义属于**采集侧**(只看原始 `content`,清洗结果另立列,清洗不得回写标签)。写入点必须逐行计算,不许用 DDL 默认值当判定。库里存了什么就必须能被发现:`doctor` 按真实值反查(谎报/低估/词表外值),对不上就 WARN/FAIL —— 不能靠"当初写对了"。改历史数据要三件套:默认干跑出逐行 `id/from/to/证据` 报告 → `BEGIN IMMEDIATE` + 逐行 CAS(标签被别人动过就整笔回滚,抛 `CompletenessConflict`)→ 报告可直接 `--rollback` 精确复原。回填前后要用字节级原像逐列比对:只准目标列变,其余列逐行不变。(2026-11-15,C-1)
29. **复用别人的函数前必须读它的函数体,副作用先查**:同名不同址的坑是真的 —— `scripts/backup.py` 的轮转(删最老快照)在 `snapshot()` 里而不是 `main()` 里,C-1 整改前误调 `snapshot()` 配 `backup_keep=7`,当场静默删掉两个历史备份,日志零痕迹。所以:调用前先读实现,确认它是否删文件/轮转/写生产;任何自动删除都必须逐条打日志(`backup.pruned`);"保留 N 份"与"绝不删旧备份"冲突时,以不删为准(提高 `disk.backup_keep`,`<=0` = 全留),磁盘压力交给 `doctor` 的 `disk.*` 报警再决策。(2026-11-15,C-1 事故)
30. **第三方依赖的 API 会漂移,"当初核验过"不算数**:核验必须常驻成体检项 —— `ttxt doctor` 的 `crawler.stack.*` 检查已装版本、Scrapling 浏览器/HTTP 实参是否命中词表(词表从 `scrapling.engines._browsers._types.__annotations__` 取,**不能**用 `get_type_hints`,0.5.1 上会炸)、可执行文件是否存在、启用的浏览器来源数、profile 体积;浏览器实参漂移 = FAIL。同一批里无界缓存必须在**源头**封顶(规则 17):浏览器磁盘缓存用 `--disk-cache-size`(`browser.disk_cache_mb`,默认 64MB),不能只靠 `housekeep` 事后按最旧文件删 —— 那是在删 Chromium profile 内部文件。(2026-11-15,P15)
31. **采集与清洗必须是一条链,而且覆盖率要能被体检发现**:C-4 实测根因不是"清洗太慢"(6 个命名空间 328 行全量清洗实测 4.3 秒),而是采集入口 `_execute_job` 从来没调用清洗管线,导致 328 行里只有 43 行有清洗文本(13%)。所以:`runner._execute_job` 插入之后当场 `pipeline.run_pipeline(category)`,统计进 `summary["pipeline"]` 与 `crawl_jobs.meta_json`;管线失败只记 `pipeline_error` + 日志 error,**不得反过来把已落库的采集判成失败**。`doctor.db.cleaned_coverage` 按库统计覆盖率,三种情况都要 WARN 并给补跑命令:完全没有清洗列(清洗列由 `migrate_articles_db` 添加,从未清洗的命名空间连列都不存在,不是值为 NULL)/ 空库 / 覆盖率落后(逐个命名空间 `已清洗/行数`)。出现"完全没有清洗列"要查是不是绕过了采集入口。(2026-11-15,C-4)
32. **测试默认不得看见生产类目库;打桩必须返回真实可解析路径**:测试会话级把 `cfg.CATEGORIES_DIR` / `ttxt_db.CATEGORIES_DIR` 默认重定向到 `07_tmp` 下的空目录(要断言仓库真实布局就显式对着 `config.PROJECT_ROOT` 断言),否则老测试只 patch system.db 忘了 patch 类目根,管线一接上就直接改写生产库(实测两次)。打桩 `store.init_articles_db` 必须返回 tmp 下真实路径:返回 `None` 会让迁移 `sqlite3.connect(str(None))`,在仓库根造出一个 4096 字节的名为 `None` 的库文件;产品侧 `store.migrate_articles_db` 现在对非路径返回值当场 `TypeError`。**绝不在测试里用 `monkeypatch.undo()` 恢复单个补丁** —— 它会把路径/日志隔离一起撤掉,后续代码直接写生产(实测事故);要恢复就重新 `setattr` 那一个目标。(2026-11-15,C-4 两次事故)
33. **删历史重复行是破坏性操作,必须[账本先行 + 三项硬约束]**:(1)**身份判定要留退路** —— 同 URL 只是同一篇文章的**充分**证据,来源页/订阅地址(``sources.load_sources()``)永远不是身份,标题/``content_hash``/``cluster_id`` 三条都对不上就进 ``identity_suspect`` 只报警不删(实测 ``demo`` 那 30 行是列表页塌陷换来的真语料,删了就毁数据);(2)**引用不许变孤儿** —— ``viral_labels``/``article_metrics``/``metric_snapshots``/``evidence_links``/``articles_fts`` 没有外键,删行时必须搬移、或丢弃并记账,事后用 ``doctor.db.orphan_references`` 反查(``article_id`` 非空却找不到文章行 = FAIL);(3)**逐行 CAS + 整笔回滚 + 可重放账本** —— 默认干跑,``--apply`` 必须配 ``--out``,账本存被删整行原文与被搬移/丢弃的引用,``--rollback`` 按原 id 复原。回滚能力不能只靠构造数据的单元测试:要把备份 zip 里的**库副本**摆到 ``07_tmp`` 下,拿**生产账本**重放[删 -> 回滚],逐行比对原 id/哈希/标题/URL/长度/簇与引用计数(``07_tmp/p17_dedupe_apply_20261115/rollback_rehearsal.py``)。跨命名空间副本只从未注册命名空间删,两个注册类目都持有就是 ``ambiguous`` 交人决定。派生索引(``articles_fts``/``article_clusters``)不进账本,删完跑 ``ttxt clean`` + ``ttxt analyze`` 重建 —— 顺带发现并修好了 FTS 长期滞后(finance 47/97、technology 62/161)。备份必须用 ``Connection.backup()``,纯复制文件会丢 WAL 内容。(2026-11-15,C-7)

38. **采集工具只准"守规矩的抓取",不得引入反检测/指纹浏览器或要授权 key 的浏览器**:规则 19 的口径是**只抓 robots 允许、无需登录、公开可读**的页面。选型实测(2026-11-15,R2-1):Scrapling 0.5.1 的 ``Fetcher``/``StealthySession`` + curl-cffi + playwright 已能拿到中新网文章页正文(job 64/65/67/68 共 64 个文章页、0 错误),不需要更重的工具;CloakBrowser 每次启动强制 license key(与规则 20"不引入常驻服务/授权件"和离线可用冲突);``itbrowser-net/undetectable-fingerprint-browser`` 是不透明预编译 Chromium 分叉,自带反检测与验证码绕过,与规则 19 直接冲突 ⇒ 一律不装。UA 口径固定:robots.txt 用项目 UA ``TouTiaoSmartFactory/0.1 (+local research collector)``,正文抓取保留 ``stealthy_headers=True``;**robots 不放行就拒绝,绝不换 UA 硬试**。robots 逐 URL 门禁 + host 级缓存,计划阶段预门禁,绝不产生注定失败的任务。(2026-11-15,P19)
39. **网络预算必须排在"本轮会不会入库"的判定之后,回执读数必须是真实的**:配额裁剪 → 关键词闸门 → 正文补全,这个顺序不能反(实测 job 66:15:53,social 第二轮 —— feed 30 条,先为它们抓了 20 个文章页耗时 33.31 s,再扔掉 19 条;整改后 job 69:16:13,同样 feed 30 条只抓 2 页 4.31 s)。每一次文章页抓取都是真实网络与时间成本,还可能触发站点限流,不能花在"本轮根本不入库"的条目上。同时 ``feed_total`` 只准写订阅源真实条数(30),不得写闸门后的剩余(11)—— 假读数会让人以为订阅源萎缩了。补全预算 ``max_item_pages`` 必须 ≥ 配额 ``max_articles``,否则一半语料是摘要级;预算用尽必须 ``LOG.warn`` + ``item_pages_capped``,让"这轮是摘要级"当场可见而不是事后发现。闸门只看标题与订阅摘要 ⇒ 召回代价要在日志里说明(``crawl.keyword_filter``)。(2026-11-15,P20)
40. **语料必须能自我变好:同一 URL + 同一标题 + 正文更长 = 就地升级,不是身份塌陷**:URL 是文章身份(规则 23/35),但"同一身份位上正文变长"是**同一篇文章拿到了更完整的正文**,按 C-7 的保留判据(正文最长者胜)就地 ``UPDATE`` 这一行 —— 保留 id / 规范化 URL / ``fetched_at``,只改 ``content/excerpt/content_hash/completeness/processor_version``,计数 ``bodies_upgraded``,不新增行、不算塌陷、也不许删除旧行;同一 URL + **不同标题**才是另一篇文章,仍计 ``url_identity_conflict`` 且**绝不改写标题**(悄悄改标题就是 ``demo`` 那 30 行的做法)。标题相等只做空白折叠 + ``casefold()``,不做相似度猜测。实测 job 64→66:第一轮 RSS 摘要 98/122 字入库,第二轮同一 URL 抓到 900+ 字却被老规则拒收,每轮重复报 3 次假塌陷 ⇒ 语料质量被永久锁死在摘要级;整改后 job 67/68 各升级 8 行,social short 8→2(avg 924.1→1127.9)、history short 8→1(avg 554.3→891.6)。升级行仍计入 ``duplicates``,所以 ``inserted + duplicates + cross_blocked == processed`` 的账不能破。(2026-11-15,P20)
41. **指标必须"归属正确 + 可信度分级合并",公开页测不到的字段一律留 NULL**:头条文章页上**属于本文章**的互动数只有两处 —— 工具条 ``div.detail-side-interaction`` 的 aria-label(实测文章 292:点赞 437 / 评论 47;文章 291:23 / 5)和评论区 ``#comment-area .title``。同页还有三处**看着像但不是**的数:推荐卡片 ``li.related-list-item p.info span``「16万阅读」(别的文章,且被"万"取整)、``div.feed-card-footer-comment-cmp``「1628评论」(别的文章)、评论行内 ``ttp-comment-like`` 下的「点赞7」(单条评论)。抓错一个数 = 往库里造假(比缺数更糟,见规则 6),所以归属写死在代码里并有测试锁住(卡片数一律不归属本文章)。**合并口径只有一处**(``metrics_import.write_metric_rows``):(a)**NULL 永不覆盖已知值**(实测 ``filled_from_null=24``,``null_kept`` 记账);(b)**可信度分级** ``verified 5 > self_reported 4 > public_page 3 > public_card 2 > unverified 1``(``config.metrics.credibility_rank`` 可调),低可信度不得覆盖高可信度(``protected_by_credibility``,并保留更强的 ``data_source/credibility``),同级才是"新的非 NULL 值胜";(c)整行全 NULL 直接拒绝并记 ``row_errors``,不写空指标。公开页**测不到就不写**:收藏数公开页仍然没有 ⇒ 恒为 NULL。**P21 这里判错过一次:「展现量公开页根本没有」是错的** —— 只翻了渲染后的可见 DOM,没查页面内嵌的结构化 JSON;P22 实测公开文章页内嵌 `<script id="RENDER_DATA">`(percent-encoded JSON)里有 `readCount`(阅读)与 `showCount`(展现),文章 292 = 8937 / 111790,与工具条点赞 437、评论 47 同源 ⇒ `reads`/`impressions` 现在来自公开页真值,`no_impressions` 这一档在能采到 counter 的类目里已消失,后台导出退为**交叉验证**而不是唯一来源(2026-11-15,P22 更正,详见 `08_wiki/reports/P22-render-data-metrics-20261115.md`)。每次抓取都追加 ``metric_snapshots`` 形成时序(实测 technology 12 行指标 / 14 次快照 / 2 篇各有两次;重跑 ``written=0, updated=2``,不重复行)。入口三重门禁:host 白名单(config 可调,仿冒/子域拒绝)+ robots 逐 URL 门禁(不放行就拒,绝不换 UA)+ ``--fetch-public`` 默认 dry-run,只有 ``--apply`` 才写库;``source_id`` 不在 ``authorized_sources`` 白名单直接 ``PermissionError``(exit 2)。真实语料里**禁止写入编造的指标数** —— 没有真值就让它缺着。(2026-11-15,P21)
42. **页内嵌 JSON 的计数只有"能证明属于本页文章"才许入库;口径缺字段要归一化不得代入 0;候选与标定都必须往前推进**:(1)**归属要证明,不能靠"这页看起来是这篇文章"**:`<script id="RENDER_DATA">` 的 percent-encoded JSON 里 `data.itemId` 必须 **等于从本页 URL 解析出的文章 id**(`/article/<id>`、`/group/<id>`、`/w/<id>`、`/a<id>`)才许用;没有 URL 上下文、解析不出 id、或 id 对不上 ⇒ **整块丢弃**退回工具条文本,并分别计数 `render_unattributed` / `render_mismatch`(实测 32 页:`render_ok 32`、错配 0)。`aid` 是应用 id 不是文章 id,不进 id 候选键。(2)**只认语义已证的 4 个字段** `readCount→reads / diggCount→likes / commentCount→comments / showCount→impressions`;`shareCount / repinCount / forwardCount / buryCount / danmuCount` 语义未证实 ⇒ 只进报告当证据,**绝不入库也绝不改名冒充收藏**。`showCount` 的"展现量"口径目前只有命名 + CTR 合理性(实测 8.00% / 1.69% / 0.08%)支撑,后台导出(`verified`)是它的交叉验证,对不上就暴露口径偏差 —— 有证据前把它当最强证据,不当定论。(3)**物理不可能要拦**:`showCount < readCount` ⇒ 拒写 `impressions` 并记 `sanity_rejected`(实测 32 行 0 违例);JSON 里的 `0` 是**真 0**(存 0),取不到才是 NULL(规则 6)。(4)**打分口径不得偷换**:`favorites` 结构性不可得 ⇒ **不得代入 0**,只在可观测率上按权重归一化 `Σ(w·r)/Σ(w)`,并在 `reason` + `features_json.metric_fields` 留痕可复算;核心互动(阅读/点赞/评论)缺失仍判 `incomplete_data`。(5)**候选必须轮转**:只按 id 倒序取前 N ⇒ 每轮反复采同一批新文章,标定样本永远攒不到 `MIN_CALIBRATION_SAMPLE=30`(实测:改前第二批仍会选中同一批 20 篇)。取候选要 `LEFT JOIN article_metrics` 后 `ORDER BY (captured_at IS NULL) DESC, captured_at ASC, id DESC` —— **没测过的先采,都测过则最久没刷的先刷**(实测改后第二批 12 篇全是新文章)。(6)**标定是三步不是两步**:先按当前指标重算标签(标定统计的是"已测得"的标签行,少这一步样本数读成 0)→ 标定 → **标定成功后必须按新阈值再重算一遍**(少第三步库里就留着默认阈值的旧标签;老代码的 `if status != "calibrated"` 恰好把它跳过了)。样本不足必须老实返回 `insufficient_sample`(实测 20/30 拒绝),攒够后实测 `32/30 ⇒ calibrated`,阈值 `p90/p60/p25 = 0.0567/0.0247/0.0113` 持久化在 `articles_meta.viral_calibration`。(7)**取证手段不全不得下"根本没有"的结论**:P21 只看可见 DOM 就宣布展现量不可得,把全项目卡在 `no_impressions`;结论只允许覆盖**已被探明的范围**(规则 15/16)。(2026-11-15,P22)
43. **身份判定必须收口:同一标题的正文抖动不算塌陷;被拒插入必须有计数;磁盘口径必须闭合**:(1)同一 URL + **同一标题** + 正文**不比已存长** ⇒ 这是同一篇文章被重新抓了一次,按 C-7「正文最长者胜」**保留原行**,计数 `bodies_kept_existing` + `LOG.info("insert.body_kept_existing")`(带 `article_id/old_chars/new_chars`),仍计入 `duplicates`;`url_identity_conflict` 这个词**只留给标题不同**(或同批内同 URL 两次正文不同、库里还没有行可比)的真塌陷。实测根因(`07_tmp/r26_identity_conflict/`):job 66 报的 3 条"塌陷"就是库里 id 13/16/20 三行,标题逐字相同、`completeness='full'`、正文 708/846/684 字;21:23 只读复现同一页 `div.left_zw` 又取到 708/846/684 字(第二个选择器 `div.content_maincontent_content` 每篇多 14 字)⇒ **哈希跨轮抖动**,而 job 66 `items_enriched=20 / item_page_errors=0` 证明当时抓的确实是文章页正文,不是摘要退化。老口径(P20 只放行"更长")让注册类目每天喊假警报,真塌陷反而被噪声埋掉;P20 的"就地升级"通道不变,只补上它管不到的反向情形。(2)**"库里没有"与"被拒了"必须是两个数**:体检只普查已存行 ⇒ 检测盲区,所以 `ttxt doctor` 新增 `crawler.insert_judgements`,按 24h 窗口统计日志里的 `insert.url_identity_conflict / page_url_collapse / body_kept_existing / body_upgraded / no_item_link`,塌陷非零即 WARN 并列出集中的 类目/来源;WARN 里必须写清整改方向是**修抽取器**(配 `link_selector`/正文选择器),不是删数据(规则 33)。(3)**磁盘预算不得只统计白名单桶**:桶是允许清单,漏登记的一级目录就是预算盲区 —— 实测根目录 6.60 GB 而 `housekeep.report()` 报 1.301 GB,差值全在没登记的 `资产库`(4.544 GB)与真正的暂存根 `07_tmp`(0.753 GB,当日 +333 MB),而 `paths.temp`/`TEMP_DIR` 指向几乎为空的 `99_temp`(3.5 MB)⇒ 暂存 TTL 与限额从未真正生效。所以 `MAJOR_PATHS` 必须登记 `07_tmp`(scratch)与 `资产库`(assets)与 `.git/.secrets`,`report()` 必须按根目录逐子项核算并列出**未登记占用**(`root_total_gb`/`unaccounted_bytes`/`unaccounted_dirs`),体检出 `disk.root_budget`/`disk.scratch`/`disk.accounting`。**只测量 + 告警,不自动删**:`07_tmp` 里是往轮账本与取证件(规则 29 的每一条自动删除都要留账,没账就不删),把 `TEMP_DIR` 改指 `07_tmp` 换 TTL 等于销毁证据,禁止。(2026-11-15 体检 §4.5/§9.1,P23)
