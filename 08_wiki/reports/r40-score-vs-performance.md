## 2. 表现分构造口径(两池分开,绝不合并)

沿用现有 `viral.py`,不新造尺子:

1. `measured` 池:曝光/阅读/点赞/评论齐全时,分数 = 0.40×阅读率 + 0.20×点赞率 + 0.15×评论率 + 0.25×收藏率(收藏缺失时按可观测率归一化,不代 0)。读数均值:technology 0.0332、finance 0.0340、health 0.0230、history 0.0323、social 0.0256。
2. `measured_reads` 池:只有阅读量时,分数 = `reads/(reads+1000)` 的单调映射。读数均值:finance 0.0802、social 0.0904。

两池的阈值、meta key、样本完全分开;本报告**没有任何一行把两池混在一起算相关性**。

## 3. 相关性对照:评分能否预测表现

### 3.1 可对照样本只有 technology 的 19 对

| 类目 | prediction_records | 已回填 outcome | 可做相关 |
|---|---:|---:|---|
| technology | 40 | **19** | 是(仅描述) |
| finance | 20 | 0 | 否 |
| history | 20 | 0 | 否 |
| health | 0 | 0 | 否 |
| social | 0 | 0 | 否 |

`outcome_score` 只从 `measured` 池回填,finance/social 虽有 7,596 / 25,411 条阅读量样本,但 `predicted_score` 与 `measured_reads` 池**零重叠**(敏感性对照 n=0),因此没有"再凑一些样本"的空间 —— 也不去凑。

### 3.2 technology n=19 的实测

| 指标 | 读数 |
|---|---:|
| Spearman 秩相关 | **-0.06** |
| MAE | 0.0180 |
| 平均偏差(预测−实际) | **-0.0127**(系统性低估) |
| 预测分不同取值数 | **3** |
| 实际分不同取值数 | 18 |

按预测分分组(只有一个桶内取值,所以实际就是按桶):

| 桶 | n | 预测均值 | 实际均值 | 排序 |
|---|---:|---:|---:|---|
| number | 10 | 0.0263 | 0.0338 | 预测第 1 / 实际第 2 |
| plain | 6 | 0.0245 | **0.0485** | 预测第 2 / 实际 **第 1** |
| question | 3 | 0.0156 | 0.0231 | 预测第 3 / 实际第 3 |

**最明显的错位**:plain 桶实际表现最高(0.0485),比 number 桶高 0.0147(相对高 43%),但预测把它排在 number 之后。

中位数分组不可用:中位数恰好等于 0.0263,10 条并列入中位,高分组 **0 条**。能形成的最大组间对比就是上表的 number vs question(0.0338 vs 0.0231),而且方向与预测一致只是巧合 —— 真正的错位在 number vs plain。

### 3.3 样本是否足够

- n=19 < 30 的项目内部下限;若要看 r≈0.3 的相关(α=0.05,power=0.8),约需 **85 对**。当前 95% 置信区间(Fisher z)约 **[-0.50, 0.41]**,横跨正负。
- 19/40 的回填还带选择偏差:能回填的是"预测后同轮就拿到 measured 指标"的文章,不是随机抽样。
- **结论:样本不足,不能宣称评分能预测表现,也不能宣称不能;更不允许外推到 finance/health/history/social(这些类目 0 对)。**

## 4. 不一致的归因与最小改动方案(本轮不改实现)

### 4.1 归因:主要是评分口径问题,数据问题是次因

1. **口径问题(主因)**:`predicted_score` = 桶均值,桶只有 3 个 ⇒ 全类目最多 3 个不同预测值,**结构上无法给文章排序**;而桶均值的排序(question < plain < number)与实际(question < number < plain)不一致,说明连"桶级先验"都没对齐。
2. **数据问题(次因)**:`outcome_score` 只接受 measured 池,finance/social 的主体是 reads-only;收藏字段全缺;指标是 2–4 天快照。
3. **写作评分那条线**:没有 draft→发布→指标的映射,属于数据链路缺失,本轮无法评估。

### 4.2 最小改动方案(仅方案,未落代码)

1. `prediction.py` 的 `_bucket` 桶均值替换为**按文章特征的连续分**(最小二乘/分位数回归,特征沿用现有 `compute_features`),训练只用 measured 池、按 "预测时点之前" 的时间切分,禁止用未来样本。
2. `prediction_records` 增加 `outcome_tier` 字段,`settle` 同时接 measured 与 measured_reads,但**评估时分池报**,不混算。
3. 评估口径改为 Spearman + top-decile lift,强制输出 n 与置信区间;n<30 一律 `insufficient_sample`,当前 `min_samples=5` 提高到 30。
4. 每类目单独建模,不共享阈值。
5. **不动**:A+B 门禁、事实可核率、黄金集取样规则。

**诚实的边界**:

- 句长 CV 0.39–0.42,句子长度偏均匀,是弱信号,不作强结论。
- health 草稿里残留 `**` Markdown 标记(2 处),属于输出卫生缺陷,与模板化分开记。
