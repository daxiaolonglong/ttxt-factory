## 4. 改前改后口径

| 环节 | 改前 | 改后(R57) |
|---|---|---|
| 词表准入(active→weak) | 无此判据(种子/挖词进来就 active) | 标题率<10% 且仅正文命中≥50 ⇒ weak;判定时先别名归一 |
| `score_keywords` 计分贡献 | `collected/quality/avg_len/爆款的signal` 全按标题∪正文命中 | **只按(归一后)标题命中的文章**;仅正文命中进 `signal_details.coverage_articles` 并单列 `weak_content_hits`,权重零,不进 `keyword_performance` 任何列 |
| 判定闸(runner 入库侧,R56) | 标题∪正文命中即放行 | **一字未动**(宁可多留,不制造假阴性);weak 只影响"什么值得再采" |
| 选词/高分表(`category_keywords`) | gap 优先+score 排序,不排除任何状态 | 增加 `status<>'weak'` |
| gap 判定(`auto_feedback`) | `collected=0` ⇒ gap | 代码未动;`collected` 语义变为**标题零覆盖**(规则 64 写明)。现网 效率工具 标题 0/正文 1,live 库下仍判 gap |
| 词表/别名表版本化 | 无要求 | `keywords_table_v1_2026-11-20.sql` 快照 + 别名 json v1;规则 64:改表必先另存,可回滚 |

改动文件:`ttxt/analysis/keywords.py`(别名加载 + 计分口径 + formula 字符串)、`ttxt/crawler/keyword_crawl.py`(选词排除 weak)。
未动:`store.insert_items`、runner 入库闸、已入库 919 行、schema、资产库、`00_control/config.json` 模型段。
