## 2. C-7 实测缺陷(读源码得到,不是推测)

`ttxt/model_gate/gate.py`(191 行,修改前):

1. `__init__(…, timeout_s=600.0, stale_s=1800.0)`(:55):**等待窗口 600 s < 判死阈值 1800 s**。持锁进程被硬杀后,等待方在锁可回收前就 `TimeoutError`,闸门最长不可用 30 分钟。
2. `_pid_alive`(:23-37)只看 PID 是否存在且未退出。**PID 复用**时旧锁永远判"存活" → 永久死锁;无法确认时保守返回 True(:34)同样放大该风险。
3. 无心跳/续租:长任务持锁期间锁文件 mtime 不变,`_clear_stale`(:75-85)只能靠 PID 判断。
4. `release()`(:87-98)在 `_fd is None` 时只能按 PID 比较,拿不到令牌;持锁进程崩溃后其他进程无法通过 `release` 路径清理。
5. `self.path = Path(path)` 的默认参数 `path: Path = GATE_LOCK`(:55)在 **import 期**绑定常量 → 任何测试/调用方都无法把默认锁路径重定向到临时目录(`gate.GATE_LOCK` 的 monkeypatch 对 `FileLock()` 无效)。
6. `_clear_stale` 的 `unlink` 只捕获 `FileNotFoundError`(:84):Windows 上若句柄未释放会抛 `PermissionError`,直接冒泡到业务调用。
7. 回收日志缺原因字段(`reason`/`holder_created`),无法事后区分"进程真死"与"PID 复用"。

跨进程竞争从未被测试覆盖(现有 3 个锁测试都在同进程内,见 `10_tests/test_p10_reliability.py:103-137`、`test_p5_model_gate.py:51-70`)。

## 4. 修改计划(最小范围)

### C-7 `ttxt/model_gate/gate.py`

- 锁文件内容升级为 `"<pid> <epoch> <token> <holder_create_s>"`(ASCII,空白分隔,向后兼容两段旧格式:缺字段按 None 处理)。
- `_inspect_process(pid)` 取代 `_pid_alive`:一次 `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` 拿 `GetExitCodeProcess` + `GetProcessTimes`,返回 `(存活?, 进程启动时刻)`;`_holder_alive(pid, created)` 比较启动时刻(容差 2 s)→ **PID 复用判死**;查询失败仍保守判活(宁可等 stale 也不误删)。
- 心跳续租:获取成功后启动 daemon 线程,每 `heartbeat_s`(`max(0.2, min(30.0, stale_s/6))`)校验令牌并重写锁内容 → 刷新 mtime。令牌不匹配 → `LOG.warn("gate.lock_ownership_lost")` 并停止续租。
- `stale_s` 默认 **180 s**(远小于 600 s 等待窗口);若调用方给出 `stale_s > timeout_s`,`LOG.warn("gate.lock_stale_unreachable", …)` 明确告警而不隐式改写语义("不会错误回收"由 `age > stale_s` **AND** 持有者不可信 两个条件共同保证)。
- 默认 `path=None` → 运行期取 `GATE_LOCK`(晚绑定),使 `monkeypatch.setattr(gate, "GATE_LOCK", tmp)` 真正生效。
- `unlink` 捕获 `OSError` 并记录 `gate.lock_stale_unlink_failed`,不再让 `PermissionError` 冒泡。
- 回收日志加可追溯字段:`reason ∈ {no_pid, process_gone, exited, pid_reused}`、`holder_created`、`age_s`、`holder_token`。
- 新增 `acquired_at`/`waited_s` 结构化日志(`gate.lock_acquired`),便于对账。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 心跳线程与 `release()` 竞态 | `release()` 先置 stop event 并 `join(timeout=heartbeat_s+1)`,再关 fd/删文件 |
| 令牌校验读文件失败(短暂 IO) | 保守:读失败 → 不删、记录 `gate.lock_heartbeat_read_failed`,继续下一轮 |
| PID 复用判定误杀真持有者 | 仅在启动时刻差 > 2 s 时判死;查询失败一律保守判活;且必须同时满足 `age > stale_s` |
| 默认 `stale_s` 从 1800→180 影响生产 | 只有"持有者已被判定不可信"才会回收;真持有者有心跳刷新 mtime,不会被 180 s 判死 |
| 只读连接改变测试断言 | 仅改连接模式,SQL 与断言不变 |
| `export_skills(root=)` 新参数 | 默认 `None` → 行为与现在完全一致,生产调用方(`__main__.py`)不动 |
